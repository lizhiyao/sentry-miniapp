# 微信页面回放项目验收

本文供维护者和参与验证的用户复核实验性页面布局回放。接入与参数以[回放指南](https://sentry-miniapp.pages.dev/guide/page-replay)为准；结果和未完成事项集中记录在 [#533](https://github.com/lizhiyao/sentry-miniapp/issues/533)，不要因为构建或请求成功就勾选完整验收。

## 固定验收对象

每次记录 Git 提交、实际安装包的版本与 SHA256、项目／组件库／框架版本，以及设备型号、系统、微信、基础库和 Sentry 部署版本。源码候选的 package.json 版本可能与已经发布的 npm 包相同，不能只用版本号辨认产物。

使用固定演示数据和独立测试项目，不填写个人信息。记录最终生成项目，而不是未标记的业务源码。npm 组件先经微信构建，再生成标记；不要把 node_modules 作为微信组件产物。标记前后比较业务 JS、map、原绑定和样式，发现差异先定位原因。

仓库示例从下列命令开始：

```bash
corepack enable
yarn install
yarn build:replay-example
```

在微信开发者工具打开命令输出的项目，配置自己的测试 DSN、AppID 及实际 request 合法域名。先在 IDE 跑通，再将同一生成项目预览或上传到手机。真机最终网络验收关闭调试；开启调试时可能绕过域名校验。

**IDE 的模拟设备名称不算真机信息。** iOS 和 Android 各保留一份实际设备记录。工具调用 Page 方法、自定义事件或 setData 仅证明对应代码／布局路径，真实触摸、焦点、键盘和前后台冻结须分别操作。

真机调试窗口显示手机型号或收到启动日志，只能证明已有连接信息。还须确认当前连接可用、目标页面已就绪，并读回实际节点与录制结果；超时或断开时保留为连接限制，不计作功能通过。记录普通预览／体验版或真机调试等运行方式，以及是否使用工具端存储、是否跳过域名校验。

## 组件与交互

先用仓库的“页面回放”页验证嵌套组件、slot、重复列表与遮蔽，再选一个实际使用的组件库项目（如 Vant Weapp）。记录组件库精确版本，不以模拟同名组件替代真实构建。

| 操作 | 核对结果 |
| --- | --- |
| 打开页面并立即查看录制开头 | 标题、初始状态、组件与输入占位出现；不能只检查最后一帧 |
| 确认订单、更新重复列表与 slot | 状态在正确实例变化；业务回调的调用次数、this、返回和异常行为不被标记改变 |
| 打开／关闭弹窗和遮罩 | 可见浮层进入录制，关闭后消失；零面积宿主不误隐藏浮层，真实隐藏子树不残留 |
| 滚动页面和组件内列表 | 内容按祖先可见区域裁剪，滚动后的状态与指针位置可辨认 |
| 用手指操作按钮、表单与输入 | 原有交互、焦点与键盘正常；点击位置来自实际事件，不能从元素中心补造 |

若自动化返回成功但业务状态没变化，或触摸事件缺少坐标，保留为工具／验证限制，不计作点击验收通过。复杂层叠、动画和字体差异按布局投影的限制判断，不要求像素复现。

组件按钮的裸默认插槽标签应显示在内部实际文字容器，不能只在录制 JSON 中查到文字就算通过。核对默认、宿主 mask、插槽容器 mask／block、零面积宿主及重复实例；无法确定裸文字位置的项目应在生成输出前明确报错，原布局、样式与事件绑定保持不变。

分别核对 text、view 和 button 的单行文案完整可见，以及带 padding／border 的多行和显式换行。scroll-view 须在滚动前后都只显示实际视口内的内容，不因公开外层样式为 overflow:visible 而画到下方控件；遮蔽后的内容也应保持相同裁剪。对照原生界面与真实播放器画面，序列化文字存在或 jsdom 样式断言不能代替该项。

显式 text/view 内容分别验收默认、具名和组件转发插槽。每种结构同时核对公开正向对照、内部 mask／block 覆盖局部 unmask，以及容器缺失时的屏蔽占位；只有保护后的文字不出现，不能排除整段内容被错误丢弃。

## 隐私

使用两条独特的非个人信息测试串，一条放输入框，一条放敏感文字区域。核对本地录制缓冲、持久缓存、实际请求和 Sentry 播放；仅检查最终画面不足以证明发送前已遮蔽。

| 场景 | 核对结果 |
| --- | --- |
| 默认设置，含嵌套组件、slot 与重复实例 | 文字遮蔽，输入／媒体仅占位，测试串不进入录制 |
| 公开祖先内的 mask 子区域 | 子区域继续遮蔽；公开祖先的自动文字不能复制敏感后代 |
| mask 祖先内的 unmask 后代 | 后代不能越过祖先隐私规则 |
| block 组件或浮层 | 后代只有占位，不保留文字；屏蔽区域点击不录制 |
| requireConsent、撤回、再次同意 | 同意前无节点查询；撤回清空未发送录制并取消迟到查询，再次同意使用新录制 |

开发验收的 envelope 导出应有容量上限，结果区须 block，不长期保留完整录制。屏蔽发生前的业务数据不应被复制进额外日志。业务显式 setUser／解除遮蔽与自动 IP 推断分别核对。

## 生命周期与故障

| 场景 | 核对结果 |
| --- | --- |
| 真实前后台切换，包含停留后恢复 | 后台取消查询，只提交已经采样的尾段；恢复后新 ID，不沿用旧缓冲 |
| 页面切换、返回与卸载，包含查询中切换 | 完成回调仍核对页面／客户端身份；旧页面不写入新帧，不跨页面关联错误 |
| 重新初始化、close／dispose | 旧控制器永久失效；关闭查询，清空录制，释放所属订阅及持有引用 |
| stop 后前后台切换，再显式 start | 手动停止不被前台自动复活；显式 start 可开始新录制 |
| 实际无网／恢复、慢网、失败和超时 | 队列有界，恢复尝试补发，超时取消请求；业务交互仍可用 |
| 受控 429／Retry-After | 限流期间不持续请求，过期后按现有 transport 策略恢复 |
| 会话采样为 0／1、错误采样为 0／1 | 未获上传资格的缓冲不发送；错误触发上传时保留有界基线与正确归属 |
| 节点、分段字节与时长接近／超过预算 | 诊断能解释跳过或停止，内存与补发不无限增长；大帧使用多个可见节点，不能仅把一个字符串加长就认为触达字节上限 |

每个文字节点会先截取前 256 个 UTF-16 码元，再遮蔽或生成快照。分别核对长文本的截断，以及多个节点合计超过分段预算时的拒收和小帧恢复；两条路径不能互相代替。

记录故障的来源。IDE 中注入 wx.request 失败、超时或 429 可以验证集成边界，必须标为“受控故障”；它不能替代手机实际断网、冻结和存储限制。故障注入仅用于测试 DSN，宿主 API 必须在 finally 中恢复；存储使用唯一前缀，结束只删除本次创建的测试键。

验收手机持久缓存及存储限制时，确认数据写入手机端。真机调试的「使用工具端的 Storage」开启时，存储结果不能作为手机存储证据；使用手机存储的同一构建另行验证，保留独有测试前缀，不清空已有业务数据。

## 开销对照

用同一设备、同一构建、同一页面和相同步骤，分别关闭和启用 Replay。先测普通页面，再测接近节点预算的复杂页面；保持采样率、网络、页面停留时长一致，至少重复三次并记录原始值。

生产运行开销使用关闭远程调试的普通预览或体验版测量。调试模式下的数值单独注明运行方式，不替代该结果；真机调试窗口的流量包含调试通信，不能当作 SDK 上报量。SDK 上报量按实际遥测请求与录制字节核对。

- 记录节点查询耗时、操作期间帧率／卡顿、CPU 和内存；使用宿主实际可提供的测量工具，缺少的指标明确写未测，不用计时器间隔冒充帧率。
- 比较微信实际小程序包，以及 JS、WXML/WXS、map 和 npm 安装大小；map／Node 工具与发到手机的运行包分别计量。
- 记录分段数、请求数、录制字节和失败／重试量；默认错误前缓冲与全量会话录制分开测。
- 根据设备结果确定可接受阈值，再决定页面范围、采样率或默认值调整。尚无真机数据时，不宣称开销可忽略，也不凭 IDE 数值设定统一性能门槛。

## 目标后台与交付

对同一最终构建依次保留采集诊断、真实 HTTP 回执、后台录制记录、播放器截图和隐私检查；它们是不同证据。播放器核对首帧、拖动时间轴、连续分段、滚动／遮蔽、实际点击和错误双向关联。HTTP 2xx、flush 或本地 rrweb 重建均不能替代播放器。

当前后台证据来自 Sentry SaaS，自建 Replay 尚未验收。自建测试须记录精确部署版本与配置，确认 Replay 的接收、处理和播放器可用；Core 的服务端版本基线不等于这些能力已经通过。没有自建环境时，保留“未验收”的结论和接入前提，不承诺所有历史版本。

模板型入口、已使用的插件／动态库及动态路径继续拒绝自动标记；普通 WXML 框架产物按实际项目验证。框架全面适配另行设计，不能为通过验收去掉隐私边界或改业务渲染结构。

提交结果时使用下面格式，附可复核的录制／错误 ID、截图或脱敏数据；缺项明确列出，不用“全绿”概括：

```text
提交／包 SHA256：
项目／组件库／框架：
实际设备／系统／微信／基础库：
运行方式／存储来源／域名校验设置：
Sentry SaaS 或部署版本／配置：
操作步骤与故障来源：
采集／请求／播放／隐私／开销结果：
录制／错误 ID 与证据：
失败项和未验证边界：
```

发布前仍须检查同一 tarball 的 Replay 与 Node 工具入口、类型、CLI、依赖、许可和体积预算，确认主包未启用时不携带录制器、Node 工具不进入小程序运行代码。完成 issue 的验收不自动批准 npm 发布。
